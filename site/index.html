01 / INVESTIGATE

Errors with context.

Grouped issues, stack traces, breadcrumbs, tags and comments. Native JavaScript source maps reveal original source locations while preserving the raw stack.

  • Resolve and reopen issues
  • Filter by project and environment
  • Inspect original event context
02 / CORRELATE

More than a message.

Transactions, standalone spans and typed logs. Choose a time window, inspect latency percentiles and follow trace IDs into related logs.

  • Average, p50 and p95 latency
  • Exact service and time filters
  • 64-bit log integers without rounding
03 / RESPOND

Know when it changes.

HTTP, TCP and heartbeat monitors with a durable scheduler. Error-frequency and uptime rules deliver email or generic webhooks with recorded attempts.

  • Failure and recovery history
  • Persistent queues and retries
  • Owner, admin and member roles

MAKE IT YOURS

Bring Docker.
Keep your SDK.

Build the application image locally and start it alongside PostgreSQL. No separate web or worker services to assemble.

  1. 01

    Start the stack

    You need Git, Docker with Compose, and OpenSSL.

  2. 02

    Create your workspace

    Open localhost:8000, create the first account, then a project.

  3. 03

    Point your SDK at its DSN

    Copy the project DSN into your existing Sentry SDK configuration. Verify the capabilities your application needs.

TERMINAL / LOCAL SETUP
git clone https://github.com/jerolan/good-sentry.git
cd good-sentry
test -f .env || printf 'SECRET_KEY=%s\n' "$(openssl rand -hex 32)" > .env
docker compose up --build -d
↳

Keep your .env between restarts. The secret protects sessions. Configure your public domain and database credentials before exposing the stack.

A CLEAR STATUS

Useful today.
Still being built.

GoodSentry is an independent Go implementation in active development. Full Sentry compatibility and GlitchTip feature parity are not complete.

Automatic repository integrations, CLI artifact uploads, native OTLP, SSL certificate monitors and other integrations remain on the roadmap. There is no published container-registry image or verified memory target yet.
